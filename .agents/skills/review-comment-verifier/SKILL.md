# Review Comment Verifier

AIレビューを事実として受け入れず、各コメントを独立に検証して、判断、変更、commit、返信を追跡可能にする。

## 対象を確定する

1. リポジトリの指示を読み、対象PR、指定されたreviewまたはcomment URL、PRのhead/base、作業場所を確認する。
2. 指定URLの投稿者を対象AIレビュアーとして特定する。PR全体から、その投稿者による未解決のdiff review threadをすべて取得する。Conversationの通常コメント、レビュー総評、別投稿者のコメント、resolved threadは対象外とする。複数のAIレビュアーを対象にする場合はユーザーの明示指定を必要とする。
3. 既存の対象PR用worktreeをリポジトリ指定の方法で再利用する。なければリポジトリのworktree方針に従ってPR head用の専用worktreeを用意し、現在のcheckoutを暗黙に切り替えない。対象worktreeに由来不明の未コミット変更があれば編集せず停止する。

読み取り・分析だけの依頼では、commit、push、GitHubへの返信を行わない。対象コメントへの対応まで明示的に依頼されている場合は、修正、commit、push、返信までを許可範囲とする。threadのresolve、レビューのdismiss、merge、branchやworktreeの削除は行わない。

## コメントを検証する

各コメントについて、コメント対象時点と現在のPR headを区別して調べる。少なくとも、現在の対象コード、関連する呼び出し元、既存テスト、コメント後の履歴を確認する。可能なら最小再現または関連テストも実行する。行がoutdatedかどうかではなく、現在のコードで問題が成立するかを判断する。

`docs/SPEC.md`とリポジトリ規約を優先し、次に関連Issue、PR本文、実装を根拠にする。これらが矛盾する場合は暗黙に仕様を選ばず、変更と返信を保留して差異を報告する。

判定は次のいずれかにする。

- **対応必要**: 現在も指摘が成立し、PRの仕様と範囲内で修正すべき。
- **ハルシネーション**: 指摘の前提、コード解釈、仕様解釈が誤っている。
- **修正済み**: 指摘時点では成立したが、後続commitまたは別コメントの対応ですでに解消している。
- **対応不要**: 指摘は事実だが、仕様外、任意の好み、過剰設計などの理由で今回のPRでは変更すべきでない。
- **確認不能**: 必要な環境、認証、再現条件などがなく、正否を十分に確認できない。

単に再現しなかったことをハルシネーションの根拠にしない。確認不能なら変更も返信も保留し、足りない証拠と必要な確認手段を報告する。

## 修正をcommitする

対応必要なコメントは原則として1コメントにつき1commitで修正する。変更前に関連検証を選び、修正後に実行する。commit形式は次のとおりとする。

```text
fix(review): <指摘内容の短い要約>

Review-comment: <comment URLまたはID>
```

先行コメントの修正で別コメントも解消された場合は空commitや重複変更を作らず、後者にも同じcommit SHAを対応づける。各commitを独立にレビュー可能な状態に保ち、無関係な変更を混ぜない。

全コメントの処理後、`package.json`などリポジトリが指定するSSOTからformat check、lint、test、buildを特定してすべて実行する。UIやユーザーフローへ影響する場合は、リポジトリ指定のブラウザ確認も行う。必須検証の失敗、仕様矛盾、確認不能が残る場合はpushと「修正完了」の返信を行わず、再現コマンド、失敗、残るリスクを報告する。

## 公開して返信する

全必須検証に成功してからcommit群を一括pushし、その後に各対象threadへ返信する。返信には判定、簡潔な根拠、該当するcommit SHA、実施した検証を含める。

- 対応必要: `指摘を確認し、<SHA> で修正しました。<検証結果>`
- ハルシネーション: `ハルシネーションのため、対応不要です。根拠: <確認した事実>`
- 修正済み: `指摘は正当ですが、<SHA> ですでに修正済みです。根拠: <確認した事実>`
- 対応不要: `指摘内容は成立しますが、今回のPRでは対応不要です。理由: <仕様またはスコープ上の理由>`

定型文は状況に合わせて簡潔に補うが、異なる判定をハルシネーションとして返信しない。返信に失敗した場合は外部状態を再取得して投稿済みでないことを確認し、同一内容で1回だけ再試行する。解消しなければ停止し、comment URL、予定していた返信、対応SHAを報告する。

## 完了報告

対象AIレビュアーと抽出条件を示し、各コメントについてURL、判定、根拠、commit SHAまたは対応不要理由、返信結果を一覧で報告する。あわせて品質ゲート、push結果、破壊的変更の有無、保留事項と残るリスクを報告する。
