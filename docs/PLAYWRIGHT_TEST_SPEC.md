# Playwright 全画面テスト仕様書

## 1. 目的

本書は、MVP 1.0 の単一ページ内にある7画面と共通ヘッダーについて、ブラウザから操作・観測できる振る舞いを Playwright で検証する仕様を定義する。プロダクト要件の正本は [`SPEC.md`](./SPEC.md) とし、本書はテストケース、テストデータ、期待結果と自動テストの対応を示す。

## 2. テスト境界

テスト対象の公開境界はブラウザUIとする。入力、ボタン操作、画面遷移、表示、活性状態、ダウンロードをユーザーと同じ経路で検証し、Reactのstateや内部関数は直接参照しない。

AI推論は端末性能、WebGPU、数GBのモデル取得に依存するため、全画面回帰テストでは `e2e-fake` ビルドの解析境界を使用する。OCRとGemmaの成功、OCR失敗、Gemma失敗だけを制御し、画像の読込・調整、レビュー、選択、SVG/PNG/ICS生成は実装本体を通す。

次の項目はこのスイートの対象外とする。

- 実モデルによるOCRおよびGemmaの精度・性能
- 実Google OAuthとGoogle Calendar APIへの登録
- Safari、Firefox、スマートフォン固有の互換性
- ドラッグ＆ドロップ、クリップボード、切り抜きPointer Eventsの全組合せ（コンポーネントテストで補完）

## 3. 実行環境

| 項目 | 内容 |
|---|---|
| テストランナー | Playwright Test |
| ブラウザー | Desktop Chrome設定のChromium |
| ロケール | `ja-JP` |
| アプリURL | `http://127.0.0.1:4174/my-timetable/` |
| 通常ビルド確認URL | `http://127.0.0.1:4173/my-timetable/` |
| 解析 | `e2e-fake` の決定的テストダブル |
| 証跡 | 失敗時のスクリーンショット、動画、trace、HTML report |

実行コマンドは次のとおり。

```sh
bun run test:e2e:fake
```

実モデルを使用する既存の解析スモークテストは次のコマンドで実行する。全画面スイートはモデル取得を繰り返さないため、この実行には含めない。

```sh
bun run test:e2e
```

## 4. テストデータ

| データ | 用途 | 期待される内容 |
|---|---|---|
| `e2e/fixtures/timetable.png` | 正常な画像入力 | 画像調整と解析を開始できる |
| fake OCR結果 | 正常な解析 | `ALPHA` 10:00–11:00、`ベータ` 11:00–11:30 |
| fakeイベント | 正常なレビュー | `TEST FESTIVAL 2026`、開催日 `2026-09-12` |
| `schedule.txt` | 非対応形式 | MIME type検証で拒否される |
| `oversize.png` | サイズ上限超過 | 20MBを1byte超え、アップロード画面に留まる |
| `broken.png` | 復号不能画像 | MIME typeはPNGだが画像読込で失敗する |
| `e2e.analysisScenario=ocr-error-once` | OCR異常 | 初回だけ `OCR_EXECUTION_FAILED` を返し、再試行は成功する |
| `e2e.analysisScenario=gemma-error-once` | Gemma異常 | 初回だけ `GEMMA_EXECUTION_FAILED` を返し、再試行は成功する |

## 5. 画面カバレッジ

| 画面・共通領域 | 正常系 | 異常系・境界値 | 仕様 |
|---|---|---|---|
| 共通ヘッダー | テーマ・言語変更、設定維持 | E4B利用不可理由と非活性 | SPEC 5、6.1 |
| 1. トップ・アップロード | PNGを1枚取り込む | 非対応形式、複数、20MB超過 | SPEC 6.1 |
| 2. 画像調整 | 回転、明るさ、リセット、解析開始 | 復号不能画像から安全に復帰 | SPEC 6.2 |
| 3. AI解析 | 進捗表示からレビューへ遷移 | OCR/Gemma再試行、キャンセル、診断情報 | SPEC 6.3 |
| 4. 抽出結果確認 | OCR根拠、2件確認、選択へ遷移 | 必須不足、時刻矛盾、確認不可 | SPEC 6.4 |
| 5. 予定選択 | 2件選択、競合警告、バッファ変更後の解消 | 検索0件、全解除、続行不可 | SPEC 6.5 |
| 6. タイムライン編集 | タイトル、横型、サイズ変更、プレビュー | 最小幅未満のHTML制約 | SPEC 6.6 |
| 7. エクスポート | SVG、PNG、ICS保存 | 日時未確定の除外、Google利用不可 | SPEC 6.7 |

## 6. 正常系テストケース

### E2E-N-001 画像取込からファイル保存まで

対象: 全7画面

1. PNGを選択し、画像調整画面が表示されることを確認する。
2. 右90度回転と明るさ120%を反映できることを確認する。
3. リセットで明るさ100%へ戻ることを確認する。
4. 解析を開始し、解析中画面を経て結果確認画面へ進むことを確認する。
5. 予定2件と `ALPHA` のOCR根拠が表示されることを確認する。
6. 確認可能な予定を一括確認し、予定選択画面へ進む。
7. 2件が初期選択され、既定の移動時間バッファでは競合警告が表示されることを確認する。
8. 移動時間バッファを「なし」にすると競合が解消されることを確認する。
9. タイムラインのタイトル、横型レイアウト、SNS横長サイズを設定する。
10. 幅1600、高さ900とタイトルがSVGプレビューへ反映されることを確認する。
11. エクスポート画面で対象2件と表示されることを確認する。
12. SVG、PNG、ICSがそれぞれ対応する拡張子でダウンロードされ、PNGとICSの成功表示が出ることを確認する。

期待結果: 7画面を順番に完走し、ブラウザ内生成物を3形式で保存できる。

### E2E-N-002 共通ヘッダーの設定

対象: 共通ヘッダー、アップロード画面

1. ダークテーマへ切り替え、再読込後も維持されることを確認する。
2. 表示言語を英語へ変更し、画面見出しと `html[lang]` が英語になることを確認する。
3. WebGPU非対応時にGemma 4 E4Bが非活性で、利用不可理由が表示されることを確認する。

期待結果: 最小限のUI設定が保存され、利用不能なモデルを選択できない。

## 7. 異常系・境界値テストケース

### E2E-A-001 アップロード入力検証

対象: トップ・アップロード画面

- TXT入力で対応形式エラーを表示する。
- 画像2枚入力で単一画像エラーを表示する。
- 20MB + 1byteのPNG入力でサイズ上限エラーを表示する。
- いずれも次画面へ遷移しない。

### E2E-A-002 復号不能画像

対象: 画像調整、AI解析

- PNGとして受理された内容不正ファイルの解析で `IMAGE_LOAD_FAILED` を表示する。
- 失敗工程を画像準備として表示する。
- 「画像調整へ戻る」で調整画面へ復帰できる。

### E2E-A-003 OCR失敗

対象: AI解析

- `OCR_EXECUTION_FAILED` とOCR再試行、画像調整への復帰操作を表示する。
- 診断情報に工程を含め、ファイル名と出演者名を含めない。
- OCR再試行後に結果確認画面へ進み、OCR実行回数が2回になる。

### E2E-A-004 Gemma失敗

対象: AI解析、抽出結果確認

- `GEMMA_EXECUTION_FAILED` とGemmaのみの再試行を表示する。
- Gemmaだけを再試行して結果確認画面へ進む。
- OCRは1回、Gemmaは2回実行される。

### E2E-A-005 解析キャンセル

対象: AI解析、画像調整

- 解析中にキャンセルすると画像調整へ戻る。
- 解析失敗画面を表示しない。

### E2E-A-006 必須項目不足と時刻矛盾

対象: 抽出結果確認

- 空の予定では確認と次画面遷移を無効にする。
- 開始12:00、終了11:00では矛盾を表示し確認を無効にする。
- 終了13:00へ修正すると確認と遷移を有効にする。

### E2E-A-007 選択0件と検索0件

対象: 予定選択

- 一致しない検索語で空状態を表示する。
- 全解除で「タイムラインを作る」を無効にする。
- 表示中を全選択すると再び有効にする。

### E2E-A-008 カスタムサイズ下限

対象: タイムライン編集

- 幅319はHTML制約上不正、320は有効と判定される。

### E2E-A-009 日時未確定予定のカレンダー除外

対象: 抽出結果確認、予定選択、タイムライン編集、エクスポート

- 相対時刻だけを持つ確認済み予定は画像出力対象にできる。
- エクスポート画面でカレンダー対象から1件除外する。
- ICS保存とGoogle Calendar登録を無効にする。
- Google OAuth未設定理由を表示する。

## 8. 合格基準

- `screens-fake` の全テストが成功する。
- 既存の `pages-smoke` と `analysis-fake` が回帰しない。
- ページ内で未処理例外が発生しない。
- 失敗時にPlaywrightの証跡から再現手順と画面状態を確認できる。
